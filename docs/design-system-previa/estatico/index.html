Qual Design System combina com o seu painel

Li os tokens e o CSS do site em francês e em mandarim, e montei a mesma tela de Alunos com seis bibliotecas open source reais, já vestidas com as suas cores. Troque idioma e tema abaixo para ver como cada uma se comporta.

O que entendi do seu estilo

Papel e tinta, não branco e cinza

Fundo bege quente, cartões um tom abaixo, linhas suaves e texto em tinta roxa ou marrom. Nada de cinza frio de painel padrão.

Uma cor de marca por idioma

Azul no francês, vermelho laca com dourado no mandarim. O sistema precisa trocar a cor primária sem mexer nos componentes.

Nunito, redondo e legível

A mesma fonte arredondada em todos os idiomas e cursos. Só a paleta de cores muda entre francês e mandarim. Números grandes e pesados nos indicadores.

Cantos de 14px, sombra leve, pílulas

Cartões generosos, selos arredondados para situação e streak, botões de 10px. Sem bordas duras nem sombras pesadas.

Claro e escuro com contraste cuidado

Todo token tem par escuro, e texto sobre cor vívida troca de branco para tinta para passar o contraste. A biblioteca precisa respeitar isso.

Site estático, sem etapa de build

HTML e JS puros no GitHub Pages, com Supabase. Biblioteca que exige Node, Tailwind ou framework entra com custo extra.

A mesma tela, seis caminhos

Tela de Alunos do painel da professora, com dados de exemplo. Os componentes vêm de cada biblioteca; as cores, o raio e a fonte vêm dos seus tokens.

Minha sugestão

Recomendado

Pico CSS como base, com os tokens do site por cima

Das seis, é a única que une três coisas que você já pratica: nenhuma etapa de build, tema por variáveis CSS e visual sóbrio, redondo e quente. Com poucas linhas de mapeamento, o painel assume a cor de cada idioma e o modo escuro sem trocar nenhum componente. O que falta nele (selo de situação, avatar, indicador numérico) é pouco e já está escrito na prévia.

Como entrar sem quebrar nada

  1. Um único arquivo de tokens compartilhado (as variáveis --b-* da prévia), lido por fr, zh e painel.
  2. Pico só nas telas do painel de Admin, uma por vez, começando por Alunos.
  3. Selo, avatar e indicador viram três componentes próprios, documentados no próprio repositório.

Quando eu escolheria outra

  • Open Props, se você prefere controle total e não se importa em escrever os componentes. É o mais próximo do que o site já faz.
  • Tabler, se o painel crescer para gráficos, kanban e muitas telas densas, aceitando o peso e o JS do Bootstrap.
  • shadcn/ui, se você decidir reescrever o painel em React. É a melhor opção nesse caminho: o tema é só variáveis CSS e os seus tokens entram quase direto.
  • Material UI, se precisar de componentes muito complexos já prontos. Fica fiel, mas é o mais pesado.
  • daisyUI, só se um dia você adotar Tailwind com build.

O site hoje é HTML e JS puros. shadcn e Material UI são React: usá-los significa adotar uma etapa de build e reescrever as telas do painel, não só trocar o CSS. Limites desta prévia: é uma tela estática, sem os menus suspensos, janelas e gráficos do painel real; as fontes carregam do Google Fonts. Dados fictícios.
